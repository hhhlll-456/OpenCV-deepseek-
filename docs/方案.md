# 🤖 具身智能机械臂开发蓝图
**核心架构**：全自动秒级手眼标定 -> 视觉状态初始化 -> DeepSeek逻辑推理 -> 机械臂盲操执行与记忆更新

---

## 🛠️ 第一阶段：物理环境部署与“卡位”基座制作

**目标：物理锁定“坐标纸”与“机械臂底座”的相对位置。**

1. **制作QR码标定纸**
   * 用二维码生成器生成4个内容分别为 `P1`, `P2`, `P3`, `P4` 的普通二维码（建议每个 2cm x 2cm 左右，留白边）。
   * 将它们分别印在/贴在一张A4/A3白纸的四个角上。
2. **制作“卡位”硬纸板（最关键的一步）**
   * 找一块平整的硬纸板，将带有QR码的标定纸平整地用双面胶贴在硬纸板上。
   * **沿硬纸板的边缘剪出一个缺口**，让这个缺口刚好能**紧紧卡住** Dobot 机械臂的底座。
   * *效果验证：以后无论你把这套东西搬到哪个桌子上，只要把机械臂卡进缺口，QR码到机械臂中心的物理距离绝对一丝不差。*
3. **测量方块高度**
   * 用尺子量出你的正方体高度，设为 $H$（例如 30mm）。

## 📐 第二阶段：唯一一次的手动测绘（写入硬编码）

**目标：获取4个QR码在机械臂坐标系下的恒定物理坐标。**

1. 将机械臂卡入硬纸板，开机。
2. 打开 DobotStudio 软件（或使用 Python 调试脚本）。
3. 手动控制机械臂（解除电机锁定或用软件点动），将**吸盘正中心**依次对准 `P1`, `P2`, `P3`, `P4` 这四个QR码的**左上角**。
4. 记录下 DobotStudio 屏幕上显示的 4 组 $(X, Y)$ 坐标。
5. **在你的 Python 主程序开头，将这四组数据写死（硬编码）：**
   ```python
   # 永远不变的物理坐标
   DOBOT_COORDS = {
       "P1": [150, 100],  # 替换为你实际测出的XY
       "P2": [250, 100],
       "P3": [150, -50],
       "P4": [250, -50]
   }
   ```
*(恭喜你，最痛苦的手动标定工作到此永久结束！)*

## 🚀 第三阶段：每次开机的“自动启动流”（代码实现）

**目标：运行代码，0.1秒内完成标定并读取桌面初始状态。**

**步骤 3.1：全自动手眼标定 (Auto-Calibration)**
* 摄像头固定在正上方（随便哪个能看全QR码的位置）。
* OpenCV 读取一帧图像，调用 `cv2.QRCodeDetector().detectAndDecodeMulti()`。
* 提取 `P1` 到 `P4` 的左上角**像素坐标**。
* 调用 `cv2.getPerspectiveTransform()`，将刚提取的像素坐标与阶段二写死的 `DOBOT_COORDS` 进行计算，瞬间得到 `Transform_Matrix`。

**步骤 3.2：状态初始化 (State Initialization)**
* 将红、黄、蓝、绿四个方块平放在标定纸的工作区域内（**不要重叠**）。
* OpenCV 再次读取图像，转换到 HSV 色彩空间。
* 通过颜色阈值和 `cv2.findContours` 找到4个方块中心的**像素坐标**。
* 用 `Transform_Matrix` 将像素坐标转换为机械臂**物理坐标**。
* **初始化全局记忆字典（World_State）：**
  ```json
  world_state = {
      "red": {"x": 210, "y": 150, "z_level": 0},
      "yellow": {"x": 260, "y": 120, "z_level": 0},
      "blue": {"x": 180, "y": 180, "z_level": 0},
      "green": {"x": 220, "y": 200, "z_level": 0}
  }
  ```
*(注：从这一秒开始，你的程序再也不需要看摄像头了，视觉任务全部杀青！)*

## 🧠 第四阶段：DeepSeek 大脑决策

**目标：大模型理解语义，输出结构化动作。**

1. **录入用户指令**：比如“把红色放到黄色上，然后再把蓝色放到红色的左边”。
2. **构建 Prompt 并调用 API**：
   ```text
   你是一个机械臂决策大脑。当前桌面上方块的坐标和层级状态为：[传入world_state]。
   方块边长为30mm。左边代表Y轴减30，右边Y轴加30，前边X轴加30，后边X轴减30。
   请根据用户的指令，计算目标动作。
   只允许输出JSON数组，格式如下：
   [{"action": "stack", "obj": "red", "target": "yellow"}, 
    {"action": "place_coord", "obj": "blue", "target_x": 260, "target_y": 90}]
   ```
3. 接收 DeepSeek v4.1 返回的 JSON 字符串并解析。

## 🦾 第五阶段：机械臂执行与记忆刷新（闭环）

**目标：安全抓放，并在大脑中同步更新物理世界状态。**

1. **设定安全参数**
   * `TABLE_Z`：桌面抓取高度（如 -45）。
   * `CUBE_H`：方块高度（如 30）。
   * `SAFE_Z`：安全平移高度（必须极高，如 80，保证不撞到摞起来的塔）。
2. **执行循环与高度计算**
   遍历 JSON 中的动作：
   * **计算抓取点**：读取 `world_state["red"]`，计算抓取 $Z = TABLE\_Z + (z\_level \times CUBE\_H)$。
   * **执行抓取**：机械臂到 XY -> 降到安全 Z -> 降到抓取 Z -> 开吸盘 -> 升到安全 Z。
   * **计算放置点**：读取 `world_state["yellow"]`，计算放置 $Z = TABLE\_Z + (z\_level \times CUBE\_H) + CUBE\_H$。
   * **执行放置**：机械臂平移到目标 XY -> 降到放置 Z -> 关吸盘 -> 升到安全 Z。
3. **刷新记忆库（极度重要）**
   动作完成后，必须立即更新 Python 字典：
   ```python
   world_state["red"]["x"] = world_state["yellow"]["x"]
   world_state["red"]["y"] = world_state["yellow"]["y"]
   world_state["red"]["z_level"] = world_state["yellow"]["z_level"] + 1
   ```
4. 系统待命，等待你的下一句指令。

## 💡 开发顺序与排雷建议

1. **分步开发，切勿一口吃成胖子**：
   * **Day 1**：只做硬件卡位，写出识别QR码并自动计算矩阵的代码。（验证：点一下屏幕上的坐标，机械臂能不能精准走到那里）。
   * **Day 2**：写出颜色识别并生成 `world_state` 字典的代码。
   * **Day 3**：脱离机械臂，只写请求 DeepSeek API 的代码，看看打印出来的 JSON 对不对。
   * **Day 4**：把 JSON 喂给机械臂执行，加入 Z 轴高度计算和记忆刷新。

2. **气动元件的物理延迟**：
   吸盘开启（抽气）和关闭（放气）需要时间。代码里务必加上：
   ```python
   dobot.suck(True)
   time.sleep(0.5)  # 等待吸力建立，否则提起来会掉
   ```

3. **QR码识别率的保障**：
   如果开机时 QR 码识别失败，通常是因为**环境太暗**、**摄像头没对上焦**，或者 QR 码打印得太小/**没有留足够宽的白边**。确保这三点，`cv2.QRCodeDetector` 就能百发百中。

按照这个方案，你的机械臂就能在每次开机时“一眼看懂世界”，然后凭借大模型的智商和精准的内部记忆，完成非常复杂的空间堆叠任务！祝你开发顺利！
