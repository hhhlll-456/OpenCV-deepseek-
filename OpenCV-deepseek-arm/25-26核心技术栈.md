# Grok:

**MECE analysis of core AI + robotics / embodied intelligence terms (as of mid-to-late 2026), organized by tech stack from first principles, with clear links and plain-English explanations.**

I start from the simplest possible first-principle view so nothing is assumed:

**First principles of intelligence that acts in the world**  
Any useful intelligent system that can do real work must solve four fundamental problems:

1. **Perceive** the current state of the world (sensors → meaningful representation).  
2. **Understand / reason** about goals, language, and consequences (what should happen next and why).  
3. **Decide / plan** actions that move the world toward the goal.  
4. **Act** in the physical (or digital) world and close the loop with feedback.

Everything else is engineering that makes these four steps scalable, general, cheap, and reliable.  
The buzzwords you listed (and the many you didn’t) are simply different layers or techniques that attack one or more of these four problems. I group them **MECE** (Mutually Exclusive, Collectively Exhaustive) by the natural technology stack that has emerged.

---

### Layer 0 – Foundational Substrate (the “brain” material)
These are the raw computational primitives that almost everything else is built on.

- **Transformer / Attention** – the dominant neural architecture since 2017. It lets models weigh relationships between any parts of the input (words, image patches, robot states, future predictions).
- **LLM (Large Language Model)** – a transformer trained at massive scale on text so it can predict / generate language and, by extension, reason.
- **Pre-training** – the initial huge “read the internet / watch videos / observe robots” phase that creates general knowledge.
- **Scaling laws** – empirical rules that say “more data + more compute + bigger model → predictably better performance.”

Everything below sits on top of this substrate.

---

### Layer 1 – Core Model Families (what the model can take in and put out)

| Term                                   | What it is (plain English)                                 | Inputs → Outputs                                             | Main use                                                     |
| -------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **LLM**                                | Text specialist                                            | Text → Text / reasoning                                      | Pure language, planning in words                             |
| **VLM (Vision-Language Model)**        | Sees + talks                                               | Image(s) + text → text / embeddings                          | Describe scenes, answer visual questions, ground language in vision |
| **VLA (Vision-Language-Action Model)** | Sees + understands language + outputs robot motor commands | Camera image(s) + language instruction → low-level actions (joint positions, end-effector poses, gripper commands, etc.) | Direct robot control from natural language (“pick up the red cup”) |
| **World Model (WM)**                   | Internal simulator of “what happens if…”                   | Current observation + (optional) action → predicted future observation / state | Imagination, planning, data generation                       |
| **WAM (World-Action Model)**           | World Model + Action generation fused together             | Observation + language → predicted future world **and** the actions that produce it | Next-generation robot policies that plan by “dreaming” consequences |

**Key evolutionary links (2024–2026)**  
LLM → VLM (add vision) → VLA (add action head) → WAM (add explicit future-world prediction so the policy is no longer purely reactive).  
VLAs are the dominant practical robot “brain” in 2025–early 2026; WAMs are the emerging frontier because pure reactive mapping (VLA) struggles with long-horizon physics and contact-rich tasks.

**Embodied Intelligence / Physical AI / Embodied AI**  
These three terms are largely synonymous in industry usage in 2026.  
They simply mean: intelligence that is grounded in a physical body, continuous sensorimotor interaction, and real-world consequences (as opposed to pure text or pure simulation). “Physical AI” is the more commercial/marketing label; “Embodied AI / Embodied Intelligence” is the academic one.

---

### Layer 2 – Making Models Better / Specialized (Adaptation & Alignment)

Once you have a big pre-trained model, you rarely use it raw. You adapt it.

- **Prompt / Prompt Engineering** – the cheapest way to steer a model: carefully worded natural-language instructions (zero-shot, few-shot, system prompts). Still fundamental in 2026.
- **Chain-of-Thought (CoT) / Reasoning traces** – forcing the model to generate intermediate reasoning steps (“let’s think step by step”) before the final answer. Dramatically improves complex reasoning. Extended into **Tree-of-Thought**, **Graph-of-Thought**, etc.
- **SFT (Supervised Fine-Tuning)** – continue training the model on high-quality input→desired-output pairs so it follows instructions or imitates expert behavior (classic behavior cloning for robots).
- **LoRA (Low-Rank Adaptation) and variants (QLoRA, etc.)** – parameter-efficient fine-tuning. Instead of updating all billions of weights, you train tiny “adapter” matrices. Makes specialization cheap and practical on consumer GPUs.
- **RLHF / DPO / GRPO / RLAIF / Preference optimization** – alignment techniques that use human (or AI) preference data so the model prefers helpful, harmless, or high-success behaviors.
- **RL (Reinforcement Learning) / Online fine-tuning** – the model tries actions, receives rewards (or preferences), and improves. Critical for closing the sim-to-real gap and for long-horizon robot skills.
- **Imitation Learning / Behavior Cloning** – learn by copying expert demonstrations (teleoperation data, human videos). The dominant data source for most current VLAs.

These techniques apply to **both** pure language agents and embodied VLAs/WAMs. In robotics you often see “SFT on demonstration trajectories → then RL fine-tuning on real robots or in simulation.”

---

### Layer 3 – Orchestration & Agent Systems (turning a model into a useful system)

A single model call is rarely enough for complex work.

- **Agent / Agentic AI** – an LLM (or VLA) that can use tools, maintain memory, plan multi-step workflows, and loop until a goal is reached.
- **Tool use / Function calling** – the model decides when to call external functions (search, calculator, robot API, code interpreter…).
- **Memory systems** – short-term (context window), long-term (vector databases, episodic memory), working memory.
- **RAG (Retrieval-Augmented Generation)** – fetch relevant documents or past experiences before answering.
- **LangChain / LlamaIndex / CrewAI / AutoGen / LangGraph / Semantic Kernel / etc.** – software frameworks that make it easy to wire models + tools + memory + multi-agent collaboration into reliable pipelines. LangChain was early and influential; many alternatives exist in 2026.
- **Multi-agent systems** – several specialized agents (planner, critic, executor, safety checker) talking to each other.
- **MCP / A2A protocols** (emerging standards) – ways for agents and tools to communicate cleanly.

For robots these same ideas appear as hierarchical agents: a high-level language planner that calls a low-level VLA or classical controller.

---

### Layer 4 – Robotics-Specific Stack (turning decisions into reliable physical motion)

This is where pure AI meets classical robotics and hardware.

**Perception & Representation**  
Sensors (RGB, depth, force/torque, tactile, proprioception) → VLM/VLA features or explicit 3D maps / point clouds / scene graphs.

**Planning & Control**  
- Classical: motion planning (RRT, trajectory optimization), impedance/force control, inverse kinematics.  
- Learning-based: the action head of a VLA or WAM (often diffusion / flow-matching / autoregressive tokens).  
- Hybrid: high-level VLA decides “what,” low-level classical controller executes “how” smoothly and safely.

**Simulation & Data Engines**  
Isaac Sim, MuJoCo, Genesis, etc. + domain randomization + photorealistic rendering. Essential because real robot data is expensive. “Sim-to-real” transfer remains a central unsolved (but improving) problem.

**Embodiment & Morphology**  
The physical body (humanoid, manipulator arm, mobile base, soft robot…). Morphology determines what is easy or hard; a good body can make the learning problem dramatically simpler.

**Data**  
Open X-Embodiment, AGIBOT World, human video, teleoperation, synthetic data from world models. Scale and diversity of real + simulated trajectories are currently the biggest bottlenecks for generalist robots.

**Inference & Deployment**  
Edge GPUs, quantization, real-time chunking, distillation – because a robot cannot wait 2 seconds for a cloud model on every control cycle.

---

### How the pieces link together – a concrete end-to-end picture (2026 typical stack)

1. **Pre-train** a large VLM on internet-scale image-text data.  
2. **Add an action head** and continue training (SFT + sometimes RL) on robot demonstration data → you now have a **VLA**.  
3. Optionally **add future-prediction** so the same model also imagines “what the scene will look like after I act” → **WAM**.  
4. **Fine-tune** cheaply with **LoRA** on your specific robot + task.  
5. Wrap the VLA/WAM inside an **agent framework** (LangGraph-style or custom) that handles long-horizon language goals, memory, tool use (e.g., call a classical planner for precise insertion), and safety checks.  
6. Run the whole thing in a tight **perception–reasoning–action loop** on the physical robot, using simulation for data generation and testing.  
7. Continuously improve with online human corrections or autonomous exploration (RL).

That is the current practical path from “text model” to “robot that can be told in English to tidy a kitchen.”

# 3. Layer 0 — The ancient foundation: machine learning

Before LLMs or robots, there is:

## AI

Very broadly:

> **AI = machines performing tasks that require some form of intelligence.**

Inside AI:

```text
AI
├── Symbolic AI
│   ├── rules
│   ├── logic
│   └── search
│
└── Machine Learning
    ├── supervised learning
    ├── unsupervised/self-supervised learning
    └── reinforcement learning
```

### Supervised learning

Give the model:

```text
input → correct answer
```

For example:

```text
photo of cat → "cat"
```

The model learns:

> ```
> f(x) → y
> ```

------

### Self-supervised learning

Instead of humans labeling everything, construct the learning signal from the data itself.

For language:

```text
The cat is sitting on the ___
                       ↑
                    predict
```

This is hugely important because **internet-scale data cannot realistically be manually labeled**.

Modern foundation models owe much of their scale to self-supervised learning.

------

### Reinforcement learning — RL

Instead of:

> “Here is the correct answer.”

you give:

> “Try something. If it works, reward it.”

Conceptually:

```text
state → action → new state → reward
```

This becomes enormously important in robotics because robots ultimately need to **do things**, not merely generate text.

# 4. The Transformer revolution

The next term you absolutely need:

## Transformer

A Transformer is a neural-network architecture that became the dominant architecture behind modern foundation models.

Its central mechanism is:

> **attention**

Very roughly, attention lets the model decide:

> “Which pieces of the context are important to one another?”

For example:

> The robot picked up the cup because **it** was near the table.

What does “it” refer to?

Attention helps the network learn relationships like this.

You don't need to understand the matrix equations yet.

For your current purpose:

> **Transformer = the basic engine architecture underneath most modern LLM/VLM/VLA systems.**

# 6. Prompt

## Prompt

A prompt is simply:

> **the input/context you give a model to influence its output.**

For example:

```text
You are a robotics engineer.

Explain VLA to a beginner.
```

That's prompting.

The important conceptual distinction:

### Prompting ≠ training

Prompting:

```text
model weights
     │
     │ unchanged
     ▼
  prompt → answer
```

Fine-tuning:

```text
training data
     │
     ▼
update model parameters
     │
     ▼
new model behavior
```

This distinction is foundational.

# 8. Foundation models

Another crucial term:

## Foundation model

A foundation model is essentially:

> a large pretrained model intended to serve as a general-purpose base for many downstream applications.

Think:

```text
                FOUNDATION MODEL
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
        chatbot      coding       robotics
```

The basic philosophy changed from:

> Train one model for one task.

> Train one enormous general model, then adapt it to many tasks.

This is one of the most important paradigm shifts in modern AI.

# 11. RLHF / DPO

After SFT, researchers may further optimize the model according to preferences.

For example:

```text
Answer A
Answer B

human prefers B
```

The system learns:

> outputs like B are preferable.

You'll encounter:

- RLHF — Reinforcement Learning from Human Feedback
- RLAIF — Reinforcement Learning from AI Feedback
- DPO — Direct Preference Optimization
- GRPO — Group Relative Policy Optimization
- PPO — Proximal Policy Optimization

Don't memorize all of these yet.

The conceptual family is:

> **preference/alignment optimization**

------

# 12. Fine-tuning

Now zoom out.

## Fine-tuning

Means:

> Take a pretrained model and continue training it for a particular purpose.

There are several flavors:

```text
Fine-tuning
│
├── Full fine-tuning
│
└── Parameter-efficient fine-tuning
    │
    ├── LoRA
    ├── AdaLoRA
    ├── IA3
    └── other PEFT methods
```

And now we arrive at your LoRA.

------

# 13. LoRA

## LoRA = Low-Rank Adaptation

Suppose you have a gigantic pretrained model:

```text
████████████████████████
        huge model
```

You don't want to change all its parameters.

Instead:

```text
frozen base model
       +
small trainable adapter
```

The adapter learns the modification.

Hugging Face describes LoRA as a parameter-efficient fine-tuning method in which the original model weights remain frozen while low-rank trainable matrices represent the update. ([Hugging Face](https://huggingface.co/docs/transformers/peft?utm_source=chatgpt.com))

So the relationship is:

```text
Fine-tuning
     │
     ▼
   PEFT
     │
     ▼
   LoRA
```

**PEFT** is the category.

**LoRA** is one technique within that category.

------

# 14. QLoRA

You will almost certainly encounter:

## QLoRA

Basically:

> **quantized model + LoRA**

Quantization means representing model numbers using fewer bits.

For example:

```text
16-bit weights
      ↓
8-bit
      ↓
4-bit
```

This reduces memory requirements.

Then LoRA adapts the model.

So:

```text
QLoRA
=
quantization
+
LoRA
```

This is a great example of how buzzwords stack.

------

# 15. RAG

Another term you need:

## RAG = Retrieval-Augmented Generation

Suppose your LLM doesn't know your company's internal documents.

Instead of retraining the entire model:

```text
question
   ↓
retrieve relevant documents
   ↓
put documents into context
   ↓
LLM
   ↓
answer
```

That's RAG.

The conceptual distinction:

### Fine-tuning

> Change the model.

### RAG

> Give the model additional information at inference time.

This distinction is hugely important.

------

# 16. Embeddings

RAG leads naturally to:

## Embedding

An embedding converts something such as:

```text
"red cup on table"
```

into a vector:

```text
[0.13, -0.82, 0.44, ...]
```

The magic is that semantically similar things tend to have nearby representations.

So:

```text
"red cup"
       ↕
"cup that is red"
```

may be close in embedding space.

This enables:

```text
documents
   ↓
embeddings
   ↓
vector database
   ↓
semantic retrieval
   ↓
LLM
```

Important terms here:

- embedding model
- vector database
- semantic search
- chunking
- retrieval
- reranking
- context window

------

# 17. LangChain

Now your next confusing term.

## LangChain

LangChain is **not an AI model**.

It is a software framework/ecosystem for building applications around models, particularly applications involving things like:

- model calls
- tools
- retrieval
- agents
- workflows
- memory/state

Conceptually:

```text
             LangChain
                 │
      ┌──────────┼──────────┐
      ▼          ▼          ▼
     LLM        RAG        tools
      │          │          │
      └──────────┼──────────┘
                 ▼
              AI app
```

So comparing **LangChain vs LoRA vs VLA** is like comparing:

> a programming framework vs a training method vs a robotics model paradigm.

They're not competitors.

------

# 18. Agent

This is another major concept.

A traditional LLM looks roughly like:

```text
prompt → model → answer
```

An **agent** looks more like:

```text
             ┌───────────────┐
             │     MODEL     │
             └───────┬───────┘
                     │
                  reason
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
      search        code         tool
        │            │            │
        └────────────┼────────────┘
                     ▼
                 observe
                     │
                     ▼
                  reason
                     │
                    ...
```

The important conceptual change:

> **LLM = generates responses.**

> **Agent = model embedded in a feedback loop that can decide what to do next.**

This becomes extremely important for robotics.

# 19. Multimodal AI

Until now:

```text
text → model → text
```

But the real world isn't text.

A robot sees:

- images
- video
- audio
- depth

- language

So we get:

## Multimodal models

```text
           │

           │
```

# 20. VLM

## VLM = Vision-Language Model

A VLM combines visual and language understanding.

Conceptually:

```text
image + text
     ↓
   VLM
     ↓
text / representation
```

Example:

> Image: a robot arm beside a red cup

Question:

> “What object is closest to the gripper?”

VLM:

> “The red cup.”

The critical limitation:

> **A VLM can understand the world without necessarily controlling the robot.**

That's why VLM ≠ VLA.

------

# 21. VLA

Now we reach one of the most important 2025–2026 concepts.

## VLA = Vision-Language-Action model

Instead of:

```text
image + language
        ↓
       text
```

we want:

```text
image + language
        ↓
       model
        ↓
      ACTION
```

For example:

```text
Camera:
[red cup]

Instruction:
"Pick up the cup."

             ↓

             VLA

             ↓

robot action sequence
```

This is the key transition:

> **VLM understands. VLA acts.**

A recent review describes VLA models as unifying vision, language, and action data to learn policies that generalize across tasks, objects, embodiments and environments. ([arXiv](https://arxiv.org/abs/2510.07077?utm_source=chatgpt.com))

------

# 22. But what exactly is an "action"?

This is where robotics gets much more interesting.

An LLM outputs:

```text
tokens
```

A robot needs:

```text
motor commands
```

For example:

```text
joint 1 → 0.42 rad
joint 2 → -0.17 rad
...
gripper → close
```

or:

```text
end-effector:
x, y, z
roll, pitch, yaw
```

or a trajectory:

```text
a₁, a₂, a₃, ... aₙ
```

Therefore, a VLA has to bridge:

> **semantic intelligence → physical control**

That is much harder than generating text.

# 23. Embodied AI / Embodied Intelligence

Now the big umbrella term:

## Embodied AI

The central idea:

> Intelligence is not merely about processing information; an intelligent agent must interact with an environment through a body.

So:

```text
Traditional AI

data → model → output


Embodied AI

              ┌─────────────┐
              │   AGENT     │
              │             │
              │ perception  │
              │ reasoning   │
              │ planning    │
              │ control     │
              └──────┬──────┘
                     │
                   BODY
                     │
                     ▼
                ENVIRONMENT
                     │
                     │ feedback
                     └──────────►
```

**Embodied intelligence** is therefore broader than VLA.

It can include:

- robots
- autonomous vehicles
- drones
- simulated agents
- embodied virtual agents
- navigation
- manipulation
- locomotion
- interaction with humans

So:

> **Embodied AI = broad research paradigm.**

> **VLA = one important model paradigm within embodied AI.**

# 24. Classical robotics still matters!

This is a very important point for someone entering from AI.

It is tempting to think:

> “VLA replaced robotics.”

No.

Modern robotics still contains enormous amounts of classical engineering.

A traditional robotics stack might look like:

```text
Sensors
   ↓
Perception
   ↓
Localization / state estimation
   ↓
Mapping
   ↓
Planning
   ↓
Control
   ↓
Actuators
```

Important classical terms include:

### Perception

Computer vision, object detection, segmentation, depth estimation.

### Localization

> Where am I?

### Mapping

> What does the environment look like?

### SLAM

**Simultaneous Localization and Mapping**

A robot simultaneously:

> estimates its position + builds a map.

### Planning

> What path/action sequence should I take?

Examples:

- path planning
- motion planning
- task planning

### Control

> How exactly do I make the motors execute the desired trajectory?

Examples:

- PID
- model predictive control (MPC)
- impedance control
- force control
- inverse kinematics
- whole-body control

These aren't obsolete because AI exists.

# 25. The most important robotics distinction: task vs motion

Imagine:

> “Put the apple into the bowl.”

There are actually two problems.

### High-level task

```text
find apple
→ grasp apple
→ move apple
→ release apple
```

### Low-level motion

```text
joint angles
→ velocity
→ torque
→ motor command
```

This creates a hierarchy:

```text
LANGUAGE
   ↓
TASK REASONING
   ↓
TASK PLAN
   ↓
MOTION PLAN
   ↓
CONTROL
   ↓
MOTOR
```

Modern foundation models increasingly attack the upper part.

Classical robotics remains extremely important at the lower part.

------

# 26. Why VLA is such a big deal

Historically, robotics was often:

```text
Perception model
      ↓
Task planner
      ↓
Motion planner
      ↓
Controller
      ↓
Robot
```

Each component had to be engineered.

The dream of VLA is closer to:

```text
image + language + robot state
             ↓
          foundation
            model
             ↓
        action sequence
             ↓
           robot
```

In other words:

> **Can we create something analogous to an LLM, but for general-purpose physical action?**

That's the deeper significance of VLA.

------

# 27. But VLA has a fundamental problem

Suppose I tell a VLA:

> “Push this glass toward the edge.”

It has to understand:

```text
If I push here
      ↓
glass moves
      ↓
perhaps falls
      ↓
bad outcome
```

The model therefore needs some understanding of:

> **how the physical world evolves.**

This leads directly to the next major concept.

------

# 28. World model

A **world model** tries to model the dynamics of the environment.

Very simplified:

```text
current state + action
          ↓
     WORLD MODEL
          ↓
    predicted future
```

Mathematically:

$s_t, a_t \rightarrow s_{t+1}$

or:

$p(s_{t+1}|s_t,a_t)$

In vision:

```text
current video/image
       +
possible action
       ↓
world model
       ↓
what will happen?
```

This is powerful because the robot can effectively ask:

> “What if I do this?”

before actually doing it.

------

# 29. Why video models suddenly matter to robotics

This is one of the big 2026 developments.

Humans learn physics partly by watching the world.

If you see:

```text
ball rolling toward cup
```

you develop expectations about:

- motion
- collision
- gravity
- objects
- trajectories
- interaction

Large video models can learn enormous amounts of spatiotemporal structure.

So a new idea emerges:

> Maybe a robot foundation model shouldn't only start from an LLM/VLM.

> Maybe it should start from a **video/world model**.

This leads to WAM.

------

# 30. WAM

As of 2026, when people in embodied-AI research say **WAM**, they increasingly mean:

## World Action Model

Conceptually:

```text
                 VLA
                  │
        observation + language
                  │
                  ▼
                action
```

versus:

```text
                 WAM
                  │
        observation + language
                  │
          ┌───────┴────────┐
          ▼                ▼
   predicted future     action
       world
          │                │
          └───────┬────────┘
                  ▼
             robot behavior
```

The key idea is:

> **Don't merely predict what the robot should do. Predict how the world will evolve, and connect that prediction to action.**

NVIDIA's current glossary describes WAMs as models that jointly learn how the world changes and what actions the robot can take to cause those changes. ([NVIDIA](https://www.nvidia.com/en-us/glossary/world-action-model/?utm_source=chatgpt.com))

A 2026 survey similarly frames WAMs as combining predictive state modeling with executable action generation. ([arXiv](https://arxiv.org/abs/2605.12090?utm_source=chatgpt.com))

------

# 31. VLA vs WAM

This distinction is worth putting on your wall.

|                   | VLA                    | WAM                                       |
| ----------------- | ---------------------- | ----------------------------------------- |
| Full name         | Vision-Language-Action | World-Action Model                        |
| Core question     | What should I do?      | What will happen, and what should I do?   |
| Main input        | vision + language      | vision/video + language + possibly action |
| Core prior        | VLM                    | world/video model                         |
| Output            | actions                | future + actions                          |
| Physical dynamics | implicit               | more explicitly modeled                   |
| Paradigm          | reactive policy        | predictive/action-coupled policy          |

A useful abstraction:

$\text{VLA}: p(a|o,l)$

while a WAM aims at something closer to:

$p(o',a|o,l)$

where:

- $o$ = current observation
- $o'$ = predicted future observation
- $l$ = language/goal
- $a$ = action

A current WAM survey explicitly uses this distinction between VLA, world models, and WAMs. ([World Action Models: A Survey](https://world-action-models.github.io/?utm_source=chatgpt.com))

------

# 32. A very important caveat about WAM

**WAM is much newer and less standardized terminology than LLM, VLM, or Transformer.**

The research landscape is still evolving.

Some systems call themselves WAMs when they:

- jointly predict video and action,
- predict futures and then act,
- use a world model to score candidate actions,
- use predicted future representations to train an action policy.

So don't treat:

> “WAM”

as a single universally standardized architecture.

Think of it as an **emerging design paradigm**.

------

# 33. VLM → VLA → WAM: the conceptual evolution

Here's perhaps the most useful historical sequence:

```text
                LANGUAGE
                   │
                   ▼
                  LLM
                   │
            "understand text"
                   │
                   ▼
                  VLM
                   │
        "understand vision + text"
                   │
                   ▼
                  VLA
                   │
      "vision + language → action"
                   │
                   ▼
                  WAM
                   │
   "predict world + generate action"
```

This is not a strict linear replacement hierarchy.

It's better understood as **different ways of putting intelligence into an embodied loop**.

# 35. Embodiment

# 37. Imitation learning

Suppose a human controls a robot:

A famous special case:

Essentially:

This is extremely important in modern VLA training.

# 38. Teleoperation

A human remotely controls a robot.

For example:

```text

     ↓

```

The resulting trajectory becomes training data:

```text

```

This is one of the main ways to acquire robot data.

# 39. RL in robotics

Instead of:

```text

  ↓

  ↓

  ↓

  ↓
```

# 40. Simulation

Robots have an annoying problem:

> Real-world data is expensive.

You can't run 10 billion experiments with a real robot without eventually destroying something expensive.

So:

## Simulation

Create a virtual environment:

```text
virtual physics
      +

```

Train there.

Then transfer to the real robot.

This is:

## Sim-to-real

```text

    ↓

    ↓

```

The gap between simulation and reality is called:

## Sim-to-real gap

This is a major robotics research problem.

# 43. Diffusion models

You will encounter another giant term:

## Diffusion model

Originally famous for image generation, but increasingly important for robotics.

Instead of directly predicting:

```text
action = ?
```

a diffusion-style policy can generate a trajectory by progressively denoising it.

Conceptually:

```text
random/noisy action trajectory
             ↓
          denoise
             ↓
        better trajectory
             ↓
        better trajectory
             ↓
       final trajectory
```

This has become important for action generation and VLA/WAM research.

# 44. Flow matching

Another 2025–2026 buzzword:

## Flow Matching

```text
      │
      └── Flow matching

```

# 45. Action chunking

Robots operate at high frequency.

If the AI model produces only:

```text
one motor command
```

at a time, it may be inefficient.

Instead, it can predict:

```text
a₁, a₂, a₃, ..., aₙ
```

as a chunk.

That's:

## Action chunking

Very common in modern robot learning.

This creates an important inference loop:

```text
observe
   ↓
predict action chunk
   ↓
execute part
   ↓
observe again
   ↓
replan
```

This is called:

## Receding-horizon / closed-loop control

and is conceptually related to MPC.

------

# 46. Open-loop vs closed-loop

This distinction is fundamental.

### Open-loop

```text
plan entire action
       ↓
execute
```

No correction.

### Closed-loop

```text
observe
  ↓
act
  ↓
observe
  ↓
correct
  ↓
act
  ↓
...
```

Real robots strongly benefit from closed-loop behavior because the physical world is messy.

This is one reason why simply generating a beautiful action sequence isn't enough.

## One final perspective

The apparent explosion of terminology from **2025 → 2026** is actually telling a fairly coherent story.

**2024-ish:**

> Can foundation models understand multiple modalities and reason?

# Gemini

The confusion you are feeling is entirely normal. Between 2025 and 2026, the AI industry underwent a massive paradigm shift: we stopped just teaching computers how to *talk* and started teaching them how to *act* in the physical world.

To make sense of these buzzwords from first principles, we must look at them not as isolated features, but as a biological evolution—from building a digital brain, to giving it eyes, to handing it tools, and finally, putting it inside a physical body.

Here is the complete MECE (Mutually Exclusive, Collectively Exhaustive) taxonomy, organizing these terms by how a modern AI technology stack is built from the ground up.

## 1. The Core Brain (Foundation & Reasoning)

*These terms define how an AI thinks, learns, and processes logic in a purely digital space.*

- **LLM (Large Language Model):** The foundational engine. It is a massive statistical network trained to predict the next word in a sequence. An LLM is raw intelligence without specific goals or formatting.
- **SFT (Supervised Fine-Tuning):** The behavioral training. This is how we teach a raw LLM to stop acting like an autocomplete engine and start acting like a helpful assistant by feeding it thousands of perfectly formatted Q-and-A examples.
- **LoRA (Low-Rank Adaptation):** A mathematical shortcut for training. Instead of spending millions of dollars to retrain a massive LLM's entire neural network, LoRA injects a small, lightweight "skill module" into the model, allowing for rapid, cheap updates.
- **Prompting & Chain of Thought (CoT):** The logic extraction. CoT is a technique where you force the LLM to write out its step-by-step reasoning before giving a final answer. This dramatically reduces logical errors because the model "thinks aloud."

## 2. The Senses (Perceptual Expansion)

*Intelligence is limited if it can only read text. This layer bridges the digital and physical worlds visually.*

- **VLM (Vision-Language Model):** Giving the brain eyes. VLMs map image pixels and text words into the exact same mathematical space. This allows the AI to "read" an image—like a blueprint or a photo of a messy room—just as natively as it reads a paragraph.

## 3. Software Orchestration (Digital Agents)

*How the brain interacts with digital tools before it ever touches a robot.*

- **LangChain:** The software glue. LLMs cannot inherently click buttons, search the web, or remember past chats. LangChain is a framework that connects the AI brain to external tools, calculators, and memory databases to create autonomous digital software agents.

## 4. Physical Embodiment (The 2026 Robotics Era)

*The final frontier. This is the transition from software that runs on a screen to AI that operates real-world machinery.*

- **Embodied Intelligence (Physical AI):** The overarching field of putting an AI "mind" into a physical "body" (like a humanoid or a robotic arm) so it can perceive, reason, and act in the messy, unpredictable real world.
- **VLA (Vision-Language-Action):** The reactive physical reflex. You feed the model an image and a text command (e.g., "pick up the cup"), and the VLA directly outputs the exact motor torque values required to move the robot arm. It works well, but it is fundamentally reactive—it maps observations directly to commands without an internal understanding of how its actions will alter the environment.   
- **WAM (World Action Model):** The 2026 predictive breakthrough. Unlike VLAs, WAMs jointly predict both the robot's action and the *future visual state* of the environment. Before moving, a WAM "imagines" how the physical world will change under its intervention. By simulating consequences—like knowing a glass will shatter if pushed off a table—WAMs give robots physical commonsense, marking the difference between a machine that just moves and one that truly understands physics.

In fact, RSL perfectly highlights why this landscape can be so disorienting right now—it actually stands for two massive, entirely separate breakthroughs in the 2025–2026 timeline, depending on whether you are looking at the data layer or the robotics simulation layer.

To give you a truly comprehensive, MECE (Mutually Exclusive, Collectively Exhaustive) map of the field, we have to look at the entire pipeline. Here is the complete architecture of modern AI, tracing how raw data eventually becomes physical robotic motion.

## 0. Data & Legal Infrastructure (The Fuel)

*Before a model can think, it needs data.*

- **RSL (Really Simple Licensing):** Launched in September 2025, this is essentially the "RSS for AI". It is an open XML standard that allows web publishers to define machine-readable usage rights and payment models for AI crawlers.   
- **Synthetic Data:** AI-generated datasets used to train new models when high-quality human data runs out.

## 1. Foundation Models (The Brain & Senses)

*The core neural network architectures.*

- **LLM (Large Language Model):** The baseline text reasoning engine.
- **MoE (Mixture of Experts):** An architecture that routes queries to specialized sub-networks instead of activating the whole model, saving massive amounts of compute.
- **VLM (Vision-Language Model):** Multimodal models that process camera pixels and text natively in the same mathematical space.
- **World Models:** Neural networks trained to implicitly understand physical laws (like gravity, momentum, or object permanence) by watching video, without needing explicit physics engines.

## 2. Training & Alignment (Shaping the Brain)

*How we adapt raw foundation models to behave correctly without requiring supercomputers.*

- **SFT (Supervised Fine-Tuning):** Teaching the model its final behavior using high-quality Q&A examples.
- **RLHF / DPO (Direct Preference Optimization):** Using human ratings to mathematically reward the model for better answers.
- **LoRA (Low-Rank Adaptation):** A parameter-efficient tuning method. Instead of retraining a multi-billion parameter model, you train a tiny adapter module. This makes it possible to fine-tune AI models locally on standard hardware, such as an Inspiron laptop running Ubuntu Linux.
- **CoT (Chain of Thought):** Forcing the model to generate intermediate logic steps before answering, which drastically improves reasoning.

## 3. Agentic Orchestration (Digital Actions)

*Giving the digital brain memory and the ability to use software tools.*

- **LangChain / LlamaIndex:** Frameworks that chain LLM outputs together to build complex applications.
- **MCP (Model Context Protocol):** A standardized architecture for AI agents to connect to local tools and environments—for instance, allowing AI assistants like the Claude Code CLI to securely read and edit local developer workspaces.
- **RAG (Retrieval-Augmented Generation):** Connecting the AI to a database so it can read external documents before answering a question.

## 4. Simulation & Policy Learning (The Robotics Bridge)

*Where digital brains learn to control physical bodies safely in virtual environments.*

- **Sim2Real (Simulation to Reality):** The practice of training a robot millions of times in a physics simulator (like NVIDIA Isaac Sim or Isaac Lab) before deploying the code to real hardware to avoid catastrophic physical crashes.
- **RSL-RL (Robotic Systems Lab Reinforcement Learning):** The robotics equivalent of RSL. Released by ETH Zurich, it is a highly optimized, GPU-accelerated reinforcement learning library built specifically for robotics. It serves as the training foundation for environments like Isaac Lab, allowing complex locomotion policies to be trained in minutes.
- **Imitation Learning (Behavioral Cloning):** Teleoperating a robot—like manually guiding a three-axis DOBOT Magician arm to perform vacuum suction pick-and-place tasks—and training a neural network to perfectly mimic those movements.

## 5. Embodied AI & Hardware Execution (The Physical Layer)

*Deploying the intelligence to physical chassis and manipulators.*

- **Embodied Intelligence:** The overarching field of AI operating within physical machines in the real world.
- **VLA (Vision-Language-Action):** End-to-end models that take in a camera feed and a text command, and directly output motor torques.
- **WAM (World Action Model):** The 2026 leap beyond VLA. WAMs predict the physical consequences of an action before taking it, giving the robot spatial commonsense.
- **ROS 2 (Robot Operating System 2):** The industry-standard middleware (versions like Humble or Jazzy) that handles low-level hardware communication, facilitating advanced features like Cartographer for SLAM mapping and custom C++ global planner plugins.
- **Edge Compute & Low-Level Control:** The final physical execution layer. This involves running firmware, such as MicroPython on ESP32 boards, to translate AI commands into the complex inverse kinematics required for hardware like omnidirectional four-wheel Mecanum chassis.
